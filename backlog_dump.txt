3. Definition of Done
The code compiles and follows the Clean Architecture layers (Domain, Application, Infrastructure, API)
Commands have a FluentValidation validator, and business rules are enforced in the handler
Unit tests exist for the handler and all tests pass
The endpoint is documented in Swagger with its response codes
The change is committed on a feature branch with a Conventional Commits message
4. User Stories
E1 — Authentication & Authorization
Epic: Users can create an account and sign in securely, and every protected endpoint is limited by role.
US-01 — Register
As a
New visitor
I want to
register with my email, password, full name and role (Organizer or Attendee)
So that
I can use the platform with the right permissions
Acceptance Criteria (Given / When / Then)
Given a valid and unused email with a strong password, When I register, Then the account is created, the password is stored as a hash and the API returns 201
Given an email that is already registered, When I try to register with it, Then the API returns 409 Conflict
Given a password shorter than 8 characters or an invalid email, When I register, Then the API returns 400 with the validation errors
Priority: High     Story Points: 3     Phase: 2
Task Breakdown — US-01
#
Task
1
Add the User entity and the EF Core migration
2
Implement RegisterCommand, its handler and its validator
3
Add a password hasher service (BCrypt) behind an interface
4
Add the POST /api/auth/register endpoint
5
Write unit tests for success and duplicate email
US-02 — Login
As a
Registered user
I want to
log in with my email and password
So that
I get a token to call protected endpoints
Acceptance Criteria (Given / When / Then)
Given valid credentials, When I log in, Then the API returns 200 with a JWT that contains my user id and role
Given a wrong email or password, When I log in, Then the API returns 401 without saying which one was wrong
Given a protected endpoint, When I call it without a token, or with the wrong role, Then the API returns 401 or 403
Priority: High     Story Points: 3     Phase: 2

Write tests for valid and invalid login
E2 — Event Management
Epic: Organizers create and publish events, and anyone can browse and view upcoming events.
US-03 — Create Event
As a
Organizer
I want to
create an event with a title, description, location, category, start date and total seats
So that
attendees can find it and book it once I publish it
Acceptance Criteria (Given / When / Then)
Given I am a logged-in organizer and the data is valid, When I create an event, Then it is saved as Draft, AvailableSeats equals TotalSeats and the API returns 201
Given a start date in the past or TotalSeats below 1, When I create an event, Then the API returns 400 with the validation errors
Given I am logged in as an attendee, When I try to create an event, Then the API returns 403 Forbidden

Organizer who owns a draft event

publish the event

Given an event that belongs to another organizer, When I try to publish it, Then the API returns 403 Forbidden
Given an event that is already Published, Completed or Cancelled, When I try to publish it, Then the API returns 409 Conflict

E3 — Reservations & Payment
Epic: Attendees reserve seats, pay within a limited time or cancel, and seats are never oversold.
US-07 — Reserve Seat
As a
Attendee browsing an upcoming event
I want to
reserve one or more seats for the event
So that
the seats are held for me while I complete the payment
Acceptance Criteria (Given / When / Then)
Given an event has enough available seats, When I reserve 2 seats, Then a Pending reservation is created, the available seats drop by 2, and it expires in 15 minutes
Given the event has fewer seats than I requested, When I try to reserve, Then the API rejects the request with 409 Conflict and no seats are deducted
Given two attendees reserve the last seat at the same time, When both requests arrive together, Then only one succeeds and the other receives 409 Conflict
Given an event that has already started or is not Published, When I try to reserve, Then the API rejects the request
Priority: High     Story Points: 5     Phase: 4
Task Breakdown — US-07
#
Task
1
Add the Reservation entity and RowVersion on Event, then create the migration
2
Implement ReserveSeatCommand, its handler and its validator (quantity 1 to 5)
3
Handle concurrency with a transaction and RowVersion, and return 409 on DbUpdateConcurrencyException
4
Add the POST /api/events/{id}/reservations endpoint and document it in Swagger
5
Write tests for the sold-out case and the two-users-one-seat case
US-08 — Confirm Payment
As a
Attendee with a pending reservation
I want to
confirm my payment before the reservation expires
So that
I receive my ticket
Acceptance Criteria (Given / When / Then)
Given I have a Pending reservation that has not expired, When my payment is confirmed, Then its status becomes Confirmed and a ticket with a unique code is created
Given my reservation has already expired, When I try to pay, Then the API rejects the payment and no ticket is issued
Given a reservation that belongs to another user, When I try to pay, Then the API returns 403 Forbidden
Priority: High     Story Points: 3     Phase: 5
Task Breakdown — US-08
#
Task
1
Add the Ticket entity and the migration
2
Add a fake IPaymentService that always succeeds (no real gateway)
3
Implement ConfirmPaymentCommand with the ownership, status and expiry checks
4
Generate a unique ticket code
5
Add the POST /api/reservations/{id}/pay endpoint and write tests

Given a reservation that belongs to another user, When I try to cancel it, Then the API returns 403 Forbidden
Given a reservation that is already Cancelled or Expired, When I try to cancel it, Then the API returns 409 Conflict

E5 — Background Jobs
Epic: Time-based rules run automatically with Hangfire, so data stays correct without manual work.
US-11 — Release Expired Reservations
As a
Event organizer
I want to
unpaid reservations to be released automatically
So that
seats are not blocked by people who never pay
Acceptance Criteria (Given / When / Then)
Given a Pending reservation is older than 15 minutes, When the recurring job runs, Then its status becomes Expired and its seats return to the event
Given the job runs twice in a row, When there is nothing new to release, Then no seats are released a second time
Given the job is registered with Hangfire, When I open the dashboard, Then it appears in the Recurring Jobs tab with the cron expression */5 * * * *
Priority: Medium     Story Points: 3     Phase: 6
Task Breakdown — US-11
#
Task
1
Add Hangfire packages and SQL Server storage, and enable the dashboard at /hangfire
2
Create IReservationJobs and ReleaseExpiredReservationsJob in Infrastructure
3
Update expired reservations and return seats in one transaction so the job is safe to repeat
4
Register it with RecurringJob.AddOrUpdate using the stable ID release-expired-reservations
5
Write a test for the job and confirm it in the dashboard
